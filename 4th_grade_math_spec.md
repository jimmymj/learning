### Product Specification Document: 4th Grade Interactive Math Learning App (CMS / NC SCOS Quarter 1 Curriculum) \#\#\#\# 1\. Executive Product Overview & Pedagogical Framework The translation of Charlotte-Mecklenburg Schools (CMS) Quarter 1 mathematics standards—built upon the Illustrative Mathematics (IM K–5) curriculum framework and aligned directly with the North Carolina Standard Course of Study (NC SCOS)—into an interactive, high-utility digital learning application represents a critical operational bridge in elementary math education. Digital learning environments for 4th-grade learners must strike an optimal balance between rigorous learning standards and intuitive, visual user interfaces. By digitizing Quarter 1 instruction, this software application provides structured, actionable practice that guides students from foundational whole-number arithmetic toward fluent fractional reasoning, supporting individual learning pathways and real-time conceptual remediation. \#\#\#\#\# 1.1 Core Purpose & Curriculum Alignment The core educational mission of this application is to bridge Grade 3 conceptual multiplication and division foundations with advanced Grade 4 fractional operations, multiplicative thinking, and number-theory concepts. Grounding interactive modules in the CMS Quarter 1 sequence ensures that students construct strong concrete and visual representations before engaging with symbolic abstraction. Note that while CMS Unit 3 ("Extending Operations to Fractions") spans both Quarter 1 and Quarter 2, the Quarter 1 application scope specifically addresses foundational decomposition, addition/subtraction of fractions with like denominators, and multiplying whole numbers by unit fractions ( \$n \\times \\frac{1}{b}\$ ). | CMS Quarter 1 Unit | NC SCOS Standards | Primary Learning Objectives | | \------ | \------ | \------ | | **Unit 1: Factors and Multiples** | **NC.4.OA.4** | Find all factor pairs for whole numbers 1–100; demonstrate understanding that a whole number is a multiple of each of its factors; determine whether a whole number (1–100) is prime or composite; recognize number patterns. | | **Unit 2: Fraction Equivalence and Comparison** | **NC.4.NF.1**

**NC.4.NF.2** | Explain and demonstrate fraction equivalence ( \$a/b \= (n \\times a)/(n \\times b)\$ ) using visual fraction models; compare two fractions with different numerators and different denominators (limited strictly to denominators **2, 3, 4, 5, 6, 8, 10, 12, 100** ) using benchmark fractions ( \$0, 1/2, 1\$ ). | | **Unit 3: Operations with Fractions (Q1 Scope)** | **NC.4.NF.3NC.4.NF.4** | Decompose a fraction into a sum of unit fractions ( \$\\frac{3}{8} \= \\frac{1}{8} \+ \\frac{1}{8} \+ \\frac{1}{8}\$ ); add and subtract fractions and mixed numbers with like denominators; multiply a whole number by a unit fraction ( \$n \\times \\frac{1}{b}\$ ) using repeated addition length models. | \#\#\#\#\# 1.2 Pedagogical Principles & Visual Modeling Architecture To maximize mathematical comprehension for 4th-grade learners, the application systematically transitions instruction away from abstract symbolic manipulation toward concrete, visual representations. Key architectural principles include: 1\. **Visual Model Dominance** : Operational problems feature interactive visual models—specifically Area Models, Grid Arrays, Tape Diagrams, Fraction Strips, Dual Number Lines, and Length Models. Concepts are developed through visual manipulation prior to presenting purely numerical algorithms. 2\. **Low-Text, Intuitive User Experience (UX)** : Text instructions are brief, written at an accessible reading level, and reinforced with intuitive drag-and-drop, tap-to-split, and snap-to-grid slider interactions. Graphical navigation relies on standardized visual cues rather than dense textual prompts. 3\. **Strict UI Specification Constraints** : All visual layouts and interactive UI elements are specified using standard structured text and Markdown tables. Front-end specifications avoid external non-renderable graphic formats, raw preformatted code blocks, or mermaid diagrams, ensuring complete compatibility with standard web and native UI rendering engines. Having established these foundational product principles and structural curriculum mappings, the specification transitions to the functional requirements for Module 1\. \#\#\#\# 2\. Module Specification 1: Factors and Multiples (Standard NC.4.OA.4) Module 1 targets standard **NC.4.OA.4** , which plays a strategic role in developing multiplicative thinking and number-theory readiness. It builds upon Grade 3 equal-group concepts to prepare students for multi-digit multiplication, division, and fraction operations. \#\#\#\#\# 2.1 Learning Targets, Vocabulary, & Mastery Criteria Students must achieve mastery across whole numbers from 1 to 100 in three core areas: identifying all factor pairs of a given whole number, determining whether a single-digit number is a factor of a given whole number (and generating multiples), and correctly categorizing whole numbers as prime or composite. \* **Factor** : A whole number that divides another whole number evenly without a remainder. \* **Multiple** : The product of a given whole number and any other whole number (e.g., skip-counting sequences). \* **Factor Pair** : Two whole numbers multiplied together to produce a specific target product. \* **Prime Number** : A whole number **greater than 1** that has **exactly two unique positive factors** : 1 and itself. \* **Composite Number** : A whole number that has **more than two factors** . \#\#\#\#\# 2.2 Interactive & Visual App Feature Requirements \* **GridArrayResizerWidget** **(Area Models & Grid Arrays)** : An interactive grid canvas where students click-and-drag handles to resize rectangular arrays. For a given target whole number (1–100), the system validates whether the array dimensions represent a valid factor pair and dynamically labels the length and width dimensions. \* **MultiplicationTableHighlighterWidget** **(Interactive Multiplication Table)** : A dynamic \$10 \\times 10\$ or \$12 \\times 12\$ matrix where selecting a single-digit number animates skip-counting patterns, highlighting all multiples of that digit across the grid to visually demonstrate scale and sequence. \* **EqualGroupBundlerWidget** **(Equal-Group Bundling Canvas)** : A drag-and-drop workspace where students group discrete objects into equal sets to test whether a target whole number can be partitioned into equal groups without remainders. \#\#\#\#\# 2.3 Question Bank Generation Guidelines (20 Questions) The module question engine must generate a 20-item assessment bank distributed across three difficulty tiers: Easy (6 questions), Medium (8 questions), and Hard (6 questions). \#\#\#\#\# 5.3 Targeted Misconception Remediation Engine When a student submits an incorrect response, the application intercepts the submission and passes the state vector to the misconception diagnostic engine: 1\. **Error Pattern Matching** : The engine compares the incorrect response against known misconception keys (e.g., adding denominators together, confusing factors with multiples, or incorrect benchmark placement). 2\. **Remediation Drawer UX Behavior** : Upon detecting a matched misconception, the app presents an immediate, interactive remediation drawer. The student is then presented with a parallel item variant at the same difficulty level, allowing them to apply their remediated understanding immediately.
